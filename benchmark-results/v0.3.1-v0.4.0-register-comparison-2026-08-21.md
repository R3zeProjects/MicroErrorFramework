# MicroErrorFramework 0.3.1 vs 0.4.0 benchmark

## Method

- Baseline: immutable `v0.3.1-beta` tag.
- Candidate: `0.4.0-beta` feature branch.
- Windows 10 Pro, AMD Ryzen 7 PRO 1700X, Clang 22.1.6, Release.
- Seven independent runs per revision with alternating execution order.
- 200,000 operations per production benchmark scenario.
- Values below are medians; subsystem changes are geometric means.

## Subsystem results

| Subsystem | Change |
| --- | ---: |
| Register | **+57.1%** |
| WorkerPool | **+3.3%** |
| Sink | **+1.2%** |
| Logger | **-2.0%** |
| Async logger allocation workload | **-2.2%** |
| WorkerPool scalar dispatch matrix | **+0.8%** |

The comparison passed the feature-release regression gates: no subsystem
geometric mean regressed by 12.5% and no scalar dispatch scenario regressed by
25%.

## Register scenarios

| Scenario | `v0.3.1-beta` ops/s | `0.4.0-beta` ops/s | Change |
| --- | ---: | ---: | ---: |
| `contains_hit`, 8 producers | 3,142,520 | 6,811,990 | **+116.8%** |
| `remove`, 8 producers | 2,136,560 | 3,932,520 | **+84.1%** |
| `same_category_add`, 1 producer | 3,792,330 | 6,922,930 | **+82.6%** |
| `same_category_add`, 4 producers | 2,850,010 | 5,271,400 | **+85.0%** |
| `same_category_add`, 16 producers | 1,318,020 | 1,987,040 | **+50.8%** |
| `partitioned_categories`, 3 producers | 6,949,220 | 10,245,600 | **+47.4%** |
| `duplicate_rejection`, 4 producers | 4,977,060 | 5,464,240 | **+9.8%** |
| `capacity_rejection`, 4 producers | 4,808,390 | 5,180,170 | **+7.7%** |

The gain comes from keying register storage directly by numeric error code.
Lookup no longer hashes the category and owned message for every operation.

## Interpretation

This is a same-machine version comparison, not a universal throughput promise.
The logger's worst individual parallel-sharded row was noisy despite no logger
runtime-path change; its full subsystem geometric mean was -2.0% and remained
inside the configured gate. GitHub Actions repeats the comparison on Linux and
stores all raw CSV files as an artifact.
